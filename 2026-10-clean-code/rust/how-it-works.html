Clean Code 重構範例｜Rust 版運作說明

這頁說明 rust/ 裡的程式怎麼運作：一段故意寫得很髒的運費計算 calc()，照 Clean Code 原則重構成 shipping_fee()，再用 characterization test 窮舉 728 組輸入，證明重構沒有改變行為。範例用 Rust 1.98（edition 2024），沒有任何外部 crate，測試用內建的 cargo test，可讀性用 lizard 1.24 量化。

1. 全貌：舊版、重構版，和一個裁判

這份實作不開任何 port，也沒有外部服務。舊版和重構版算的是同一套運費規則；src/characterization.rs 是裁判，不看規格，只看兩版在同一批輸入下的結果一不一樣。

src/legacy.rs

重構前的原貌 ・ 當作行為的標準答案

一個 calc(w, r, m, a, c)，49 行（NLOC）、5 層巢狀。故意保留壞味道，不要照這樣寫。

src/shipping.rs

重構版 ・ 唯一 pub 的函式是 shipping_fee(parcel)

Parcel、Region、Membership、InvalidParcel，加上 8 個都不超過 10 行的函式（另有 Display 的 fmt）。檔頭的 //! 文件註解用白話寫出全部規則。

src/characterization.rs ＋ src/main.rs

裁判和示範 ・ ./run.sh demo

compare() 窮舉 13 × 2 × 2 × 7 × 2 ＝ 728 組輸入比對兩版。main.rs 先拿 5 筆訂單各算一次，再印出比對結果。

tests/shipping.rs ＋ tests/characterization.rs

13 個測試 ・ ./run.sh test

一邊測重構版的每條規則，一邊測「兩版結果相同」，以及「故意改壞 1 元會被抓到」。

舊版的壞味道，重構版怎麼處理

Clean Code 原則舊版 calc()重構版

按鈕是 src/main.rs 裡的 5 筆訂單。左邊是舊版 calc() 的巢狀決策樹，右邊是重構版的函式呼叫。藍色虛線是這筆訂單實際走的路，方框裡的 → 後面是那個函式回傳的值，紅色是錯誤。

本島、一般會員、訂單 800 元、2500 公克、常溫 → 100 元

舊版
calc(2500, "main", "normal", 800, false)：過了驗證 → 本島 → 一般會員 → 800 < 1000 不免運 → 在第 5 層巢狀查第 2 份重量級距：2500 ≤ 5000，100 元 → 常溫不加錢。
重構版
ships_free() 回 false（未達 FREE_SHIPPING_THRESHOLD_NORMAL 1000）→ weight_fee(2500) 回 100、region_surcharge(Region::MainIsland) 回 0 → cold_chain_fee() 回 0，shipping_fee() 回 Ok(100)。
對應測試
weight_tiers（1001～5000 公克都是 100）、free_shipping_threshold_depends_on_membership（一般會員 999 元不免運）

本島、一般會員、訂單 1000 元、800 公克、常溫 → 0 元

舊版
calc(800, "main", "normal", 1000, false)：本島 → 一般會員 → 1000 ≥ 1000，f = 0。重量完全沒被看。
重構版
ships_free() 回 true，delivery_fee() 提早 return 0;，不呼叫 weight_fee()。這就是 guard clause：條件成立就離開，不用再包一層 else。
對應測試
free_shipping_threshold_depends_on_membership（一般會員剛好 1000 元免運）

本島、金卡會員、訂單 600 元、2500 公克、冷藏 → 50 元

舊版
calc(2500, "main", "gold", 600, true)：本島 → 金卡 → 600 ≥ 500，f = 0 → 跳出巢狀後 if c 加 50。冷藏照收這條規則，要讀完整段才看得出來。
重構版
delivery_fee() 回 0（FREE_SHIPPING_THRESHOLD_GOLD 500），cold_chain_fee() 回 50。規則寫在註解裡：// 冷藏車是另外跟物流商計費的，所以免運也要收。
對應測試
cold_chain_fee_is_charged_even_when_shipping_is_free、free_shipping_threshold_depends_on_membership（金卡 500 元免運）

離島、金卡會員、訂單 3000 元、7200 公克、冷藏 → 340 元

舊版
calc(7200, "outlying", "gold", 3000, true)：r == "main" 不成立就走 else，用第 3 份重量級距：100 + ((7200 - 5000 + 999) / 1000) * 20 + 80 ＝ 240，再加冷藏 100。這裡沒有看會員等級，是因為離島本來就不免運，但程式沒寫出這個理由。
重構版
ships_free() 第一行就因為離島回 false → weight_fee(7200)：超過 5000 的 2200 公克算 3 公斤，100 ＋ 60 ＝ 160 → region_surcharge() 80 → cold_chain_fee() 離島冷藏 100。
對應測試
outlying_island_never_ships_free、cold_chain_fee_depends_on_region、weight_tiers（6001 公克是 140）

重量 0 公克 → 舊版 -1，重構版回傳 Err

舊版
calc(0, "main", "normal", 800, false) 第一個判斷就不成立，回 -1。呼叫端如果沒檢查，就會把「−1 元」當成運費。
重構版
reject_invalid() 回 Err(InvalidParcel::NonPositiveWeight(0))，shipping_fee() 裡的 ? 直接把它往外傳，後面的函式都不會執行。main.rs 用 Display 印出「重量必須大於 0 公克，收到 0」。
行為有變
這是這次重構唯一刻意改變的地方：錯誤從「混在運費裡的 -1」變成型別上分開的 Err。characterization.rs 把舊版的 -1 和重構版的 Err 都換成 Outcome::Invalid 再比較，所以 200 組無效輸入一樣算「結果相同」。
對應測試
rejects_non_positive_weight、legacy_error_code_maps_to_refactored_error

3. 一筆運費的旅程

以「離島、金卡會員、訂單 3000 元、7200 公克、冷藏」為例，也就是 src/main.rs 的第 4 筆。從示範程式建立 Parcel 到印出 340，經過這些程式碼：

  1. 建立參數物件
    src/main.rs 的 SAMPLES

    struct literal 的每個欄位都要寫名字，不會傳錯順序；地區和會員是 enum，拼錯字編譯不過。SAMPLES 是 const，Rust 的變數預設也不可變，建好就不會被改。

    Parcel {
    weight_grams: 7200,
    region: Region::OutlyingIsland,
    membership: Membership::Gold,
    order_amount: 3000,
    needs_cold_chain: true,
},
  2. 進入點只說「做了哪兩件事」
    src/shipping.rs 的 shipping_fee()、reject_invalid()

    先擋掉無效輸入，再把「配送費」和「冷藏費」相加。? 的意思是「reject_invalid() 回 Err 就直接回傳出去」，所以第二行只會在輸入合法時執行。回傳型別把「可能失敗」寫在簽名上。重量 7200、金額 3000 都合法，reject_invalid() 回 Ok(())。

    pub fn shipping_fee(parcel: &Parcel) -> Result<i64, InvalidParcel> {
    reject_invalid(parcel)?;
    Ok(delivery_fee(parcel) + cold_chain_fee(parcel))
}
  3. 判斷免不免運
    src/shipping.rs 的 delivery_fee()、ships_free()

    離島第一行就回 false，註解寫的是「為什麼」離島不免運，而不是「這裡在判斷離島」。Python 版用 dict 查門檻，這裡用 match：每種會員都得列出來，漏掉就編譯不過。

    fn ships_free(parcel: &Parcel) -> bool {
    // 離島的物流成本高，行銷部決定不開放免運
    if parcel.region == Region::OutlyingIsland {
        return false;
    }
    let threshold = match parcel.membership {
        Membership::Normal => FREE_SHIPPING_THRESHOLD_NORMAL,
        Membership::Gold => FREE_SHIPPING_THRESHOLD_GOLD,
    };
    parcel.order_amount >= threshold
}
  4. 算重量費和地區加價
    src/shipping.rs 的 weight_fee()、ceil_div()、region_surcharge()

    7200 超過 5000，多出的 2200 公克用 ceil_div(2200, 1000) 算成 3 公斤，100 + 3 × 20 = 160。離島再加 OUTLYING_ISLAND_SURCHARGE 80，配送費 240。舊版裡同一段級距邏輯抄了 3 次，這裡只有一份。

    fn weight_fee(weight_grams: i64) -> i64 {
    if weight_grams <= LIGHT_PARCEL_MAX_GRAMS {
        return LIGHT_PARCEL_FEE;
    }
    if weight_grams <= STANDARD_PARCEL_MAX_GRAMS {
        return STANDARD_PARCEL_FEE;
    }
    let extra_kilograms = ceil_div(weight_grams - STANDARD_PARCEL_MAX_GRAMS, GRAMS_PER_KILOGRAM);
    STANDARD_PARCEL_FEE + extra_kilograms * FEE_PER_EXTRA_KILOGRAM
}
    看 region_surcharge() 和 ceil_div() 的程式碼 
    fn region_surcharge(region: Region) -> i64 {
    // 用 match 列出每個地區，之後多一個地區時編譯器會逼你決定它要不要加價
    match region {
        Region::MainIsland => 0,
        Region::OutlyingIsland => OUTLYING_ISLAND_SURCHARGE,
    }
}

fn ceil_div(dividend: i64, divisor: i64) -> i64 {
    // i64::div_ceil 還沒穩定，只好自己寫。Rust 的 / 會往 0 截斷，
    // div_euclid 在除數為正時才跟 Python 的 // 一樣往下取整
    -(-dividend).div_euclid(divisor)
}
  5. 加冷藏費
    src/shipping.rs 的 cold_chain_fee()

    離島冷藏對到 COLD_CHAIN_FEE_OUTLYING_ISLAND，100 元，總計 340，shipping_fee() 回 Ok(340)。

    fn cold_chain_fee(parcel: &Parcel) -> i64 {
    // 冷藏車是另外跟物流商計費的，所以免運也要收
    if !parcel.needs_cold_chain {
        return 0;
    }
    match parcel.region {
        Region::MainIsland => COLD_CHAIN_FEE_MAIN_ISLAND,
        Region::OutlyingIsland => COLD_CHAIN_FEE_OUTLYING_ISLAND,
    }
}
  6. 舊版也算一次，並排印出
    src/main.rs 的 show_samples()、src/characterization.rs 的 case_from_parcel()

    case_from_parcel() 把 Parcel 拆回 5 個位置參數，enum 換回 "outlying"、"gold" 這些字串，再餵給 calc()。印出 離島、金卡會員、訂單 3000 元、7200 公克、冷藏 → 舊版 340｜重構版 340。

    let (weight, region, membership, amount, cold) = case_from_parcel(parcel);
let old = calc(weight, region, membership, amount, cold);
  7. 裁判窮舉 728 組
    src/characterization.rs 的 compare()、compare_with()

    同樣的對照做 728 次。legacy_outcome() 把 -1 換成 Outcome::Invalid，其他金額包成 Outcome::Fee。refactored_outcome() 先用 parcel_from_case() 把字串換成 enum，再把 Err 換成 Outcome::Invalid、Ok(fee) 換成 Outcome::Fee(fee)，然後兩邊直接比。

    看 compare() 和 compare_with() 的程式碼 
    pub fn refactored_outcome(case: Case) -> Outcome {
    shipping_fee(&parcel_from_case(case)).map_or(Outcome::Invalid, Outcome::Fee)
}

/// 比對重構版和舊版
pub fn compare() -> Comparison {
    compare_with(refactored_outcome)
}

/// 拿 candidate 的結果去比對舊版。測試會傳入故意改壞的版本，確認比對真的抓得到差異。
pub fn compare_with(candidate: impl Fn(Case) -> Outcome) -> Comparison {
    let cases: Vec<Case> = input_grid().collect();
    let outcomes: Vec<(Outcome, Outcome)> = cases
        .iter()
        .map(|&case| (legacy_outcome(case), candidate(case)))
        .collect();
    Comparison {
        total: cases.len(),
        invalid: outcomes
            .iter()
            .filter(|outcome| **outcome == (Outcome::Invalid, Outcome::Invalid))
            .count(),
        mismatches: cases
            .iter()
            .zip(&outcomes)
            .filter(|(_, (old, new))| old != new)
            .map(|(&case, _)| case)
            .collect(),
    }
}

4. 啟動時發生什麼

src/main.rs

fn main() 先呼叫 show_samples()：對 SAMPLES 的 5 筆訂單各呼叫一次 calc() 和 shipping_fee()。再呼叫 show_characterization()：跑一次 compare()，印出相同、無效、不同的組數。沒有設定檔，也不讀環境變數。

輸入網格

input_grid() 用 4 次 flat_map 把 WEIGHTS（13 個）、REGIONS（2）、MEMBERSHIPS（2）、ORDER_AMOUNTS（7）、COLD_CHAIN（2）乘開，順序和 Python 的 itertools.product 一樣。每個門檻都取「剛好、少 1、多 1」，例如 999、1000、1001。

測試

cargo test 把 tests/ 底下每個檔案各編成一個測試執行檔，共 13 個 #[test]。Python 的 24 個是 parametrize 展開後的數字；Rust 把參數化寫成測試裡的迴圈，一個 #[test] 跑多組，涵蓋的情境一樣。tests/characterization.rs 的每個測試都會重新跑一次 compare()，不含編譯不到 0.01 秒。

// src/characterization.rs
// 每個邊界都取「剛好、少 1、多 1」
pub const WEIGHTS: [i64; 13] = [
    -1, 0, 1, 999, 1000, 1001, 4999, 5000, 5001, 5999, 6000, 6001, 12345,
];
pub const REGIONS: [&str; 2] = ["main", "outlying"];
pub const MEMBERSHIPS: [&str; 2] = ["normal", "gold"];
pub const ORDER_AMOUNTS: [i64; 7] = [-1, 0, 499, 500, 999, 1000, 5000];
pub const COLD_CHAIN: [bool; 2] = [false, true];

5. 關鍵設計

先有裁判，才能放心重構

重構的定義是「不改變外部行為」。舊版沒有規格文件，只有程式本身，所以拿舊版當標準答案：同一批輸入，兩版結果要一模一樣。這種測試叫 characterization test 或 golden master，適合用在「看不懂但不能改壞」的舊程式。

裁判自己也要被測

如果 compare() 寫錯，永遠回「0 組不同」，那 728 組全部相同就沒有意義。Rust 沒有預設參數，所以拆成兩個函式：compare() 比對重構版，compare_with(candidate) 接受任何 Fn(Case) -> Outcome。comparison_catches_a_one_dollar_change 傳入一個「離島冷藏多收 1 元」的版本，斷言剛好抓到 11 × 2 × 6 ＝ 132 組不一致（離島冷藏的有效輸入數）。

fn off_by_one_on_outlying_cold_chain(case: Case) -> Outcome {
    let (_, region, _, _, cold) = case;
    match refactored_outcome(case) {
        Outcome::Fee(fee) if region == "outlying" && cold => Outcome::Fee(fee + 1),
        outcome => outcome,
    }
}

let result = compare_with(off_by_one_on_outlying_cold_chain);

兩種語言的結論一樣：舊版 CCN 15、CogC 45，重構版每個函式 CCN 不超過 3、CogC 不超過 2。差異來自語言本身：? 算一個分支、match 比 dict 查表多 1、Display 的 fmt 多一個函式、rustfmt 讓大括號和 match 分支各占一行，NLOC 變多。代價也一樣：重構版整個檔案的 NLOC 差不多是舊版的兩倍，多出來的是具名常數、兩個 enum、Parcel 和錯誤型別。Clean Code 換來的是「每一段都讀得懂」，不是「程式變短」。

其他

設計做法在哪裡
舊版保持原樣只讓 rustfmt 排版（cargo fmt --check 要過），巢狀、縮寫、魔術數字都不動，檔頭註解說明為什麼留著它。#[allow] 只列 clippy::needless_return、clippy::assign_op_pattern，因為 clippy 1.98 預設只抓到這兩個；collapsible_else_if 在這版歸在 pedantic，預設不會報，列進去也只是雜訊src/legacy.rs 的 calc() 上方
只有一個 pub 函式其他函式不加 pub，模組外面呼叫不到。Python 的底線前綴只是慣例，Rust 由編譯器擋src/shipping.rs
Result 取代例外InvalidParcel 是 enum（NonPositiveWeight、NegativeOrderAmount），實作 Display 和 std::error::Error，訊息和 Python 版逐字相同InvalidParcel
match 取代 dict 查表Python 的兩個 dict 拆成 4 個常數：FREE_SHIPPING_THRESHOLD_NORMAL、FREE_SHIPPING_THRESHOLD_GOLD、COLD_CHAIN_FEE_MAIN_ISLAND、COLD_CHAIN_FEE_OUTLYING_ISLAND，在函式裡用 match 取值。match 必須列出每個值，新增會員等級或地區時，漏掉的地方會編譯不過ships_free()、cold_chain_fee()
規則寫在檔頭//! 文件註解用白話列出 4 條規則，比讀程式快src/shipping.rs 第 1～7 行
整數用 i64重量和金額都用 i64，不用 u32：要能表示 -1 這類無效輸入，才能原封不動地和舊版比對，再由 reject_invalid() 擋掉Parcel
整數無條件進位有號整數的 div_ceil 在 Rust 1.98 還沒穩定（int_roundings）。Rust 的 / 往 0 截斷，div_euclid 在除數為正時才等於 Python 的 //，所以 -(-dividend).div_euclid(divisor) 和 Python 的 -(-a // b) 結果一樣，不經過浮點數ceil_div()
Outcome enumPython 用 int | str 加上 INVALID 字串；Rust 用 Outcome::Fee(i64)／Outcome::Invalid，比對時不會把金額和錯誤混在一起src/characterization.rs
input_grid() 用 flat_map5 層 for 迴圈會是另一種深巢狀。改成每次 flat_map 加一個維度，程式是平的，順序和 itertools.product 一樣input_grid()
舊版字串的對應放在比對端"main"、"gold" 這些字串只有舊版需要，所以對應寫在 parcel_from_case()／case_from_parcel()，shipping.rs 的 enum 不帶字串值（Python 版寫在 Enum 的值裡）src/characterization.rs
三種語言結果一致Python、.NET 版本照同一套規則實作，demo 輸出用 diff 比對逐字相同PoC 的 README「怎麼跑」
 
/// 窮舉所有維度的組合。跟 Python 的 itertools.product 一樣，前面的維度變得最慢
pub fn input_grid() -> impl Iterator<Item = Case> {
    WEIGHTS
        .into_iter()
        .flat_map(|weight| REGIONS.map(|region| (weight, region)))
        .flat_map(|(weight, region)| MEMBERSHIPS.map(|membership| (weight, region, membership)))
        .flat_map(|(weight, region, membership)| {
            ORDER_AMOUNTS.map(|amount| (weight, region, membership, amount))
        })
        .flat_map(|(weight, region, membership, amount)| {
            COLD_CHAIN.map(|cold| (weight, region, membership, amount, cold))
        })
}
