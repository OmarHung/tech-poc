Clean Code 重構範例｜Python 版運作說明

這頁說明 python/ 裡的程式怎麼運作：一段故意寫得很髒的運費計算 calc()，照 Clean Code 原則重構成 shipping_fee()，再用 characterization test 窮舉 728 組輸入，證明重構沒有改變行為。範例只用 Python 3.12 標準函式庫（dataclasses、enum、itertools），測試用 pytest 9.2 ＋ pytest-cov 7.1，可讀性用 lizard 1.24 和 ruff 0.17 量化。

1. 全貌 2. 互動流程圖 3. 一筆運費的旅程 4. 啟動時發生什麼 5. 關鍵設計 6. 怎麼跑

1. 全貌：舊版、重構版，和一個裁判

這份實作不開任何 port，也沒有外部服務。舊版和重構版算的是同一套運費規則；characterization.py 是裁判，不看規格，只看兩版在同一批輸入下的結果一不一樣。

legacy.py

重構前的原貌 ・ 當作行為的標準答案

一個 calc(w, r, m, a, c)，37 行、5 層巢狀。故意保留壞味道，不要照這樣寫。

shipping.py

重構版 ・ 唯一對外的是 shipping_fee(parcel)

Parcel、Region、Membership、InvalidParcelError，加上 8 個都不超過 9 行的函式。檔頭 docstring 用白話寫出全部規則。

characterization.py ＋ demo.py

裁判和示範 ・ ./run.sh demo

compare() 窮舉 13 × 2 × 2 × 7 × 2 ＝ 728 組輸入比對兩版。demo.py 先拿 5 筆訂單各算一次，再印出比對結果。

test_shipping.py ＋ test_characterization.py

24 個測試 ・ ./run.sh test

一邊測重構版的每條規則，一邊測「兩版結果相同」，以及「故意改壞 1 元會被抓到」。

舊版的壞味道，重構版怎麼處理

Clean Code 原則舊版 calc()重構版
有意義的命名w、r、m、a、c、fweight_grams、region、membership、order_amount、needs_cold_chain
函式短小、只做一件事1 個函式 37 行，驗證、免運、重量、地區、冷藏全擠在一起8 個函式，最長 9 行（_weight_fee）
參數越少越好5 個位置參數，呼叫端很容易把 a 和 w 傳反1 個 Parcel（參數物件），欄位有名字
不要魔術數字1000、5000、500、60、80… 散在各處LIGHT_PARCEL_MAX_GRAMS、OUTLYING_ISLAND_SURCHARGE 等具名常數
不要重複（DRY）重量級距的 if/elif 抄了 3 份只在 _weight_fee() 寫一次
用 guard clause 取代巢狀最深 5 層 if/else每個函式最多 1 層，條件不符就提早 return
用例外取代錯誤碼無效輸入回 -1，呼叫端忘了檢查就會把 −1 元當運費丟 InvalidParcelError，訊息寫出收到什麼值
讓無效狀態無法表示地區、會員是字串；拼錯的 "mian" 會被默默當成離島Region、Membership 是 Enum，Region("mian") 直接丟 ValueError
註解說明「為什麼」# 計算運費、# 加上冷藏費（只是把程式念一遍）# 離島的物流成本高，行銷部決定不開放免運

2. 互動流程圖：同一筆訂單，兩條路

按鈕是 demo.py 裡的 5 筆訂單。左邊是舊版 calc() 的巢狀決策樹，右邊是重構版的函式呼叫。藍色虛線是這筆訂單實際走的路，方框裡的 → 後面是那個函式算出來的值，紅色是錯誤。

本島、一般會員、訂單 800 元、2500 公克、常溫 → 100 元

舊版
calc(2500, "main", "normal", 800, False)：過了驗證 → 本島 → 一般會員 → 800 < 1000 不免運 → 在第 5 層巢狀查第 2 份重量級距：2500 ≤ 5000，100 元 → 常溫不加錢。
重構版
_ships_free() 回 False（未達一般會員門檻 1000）→ _weight_fee(2500) 回 100、_region_surcharge(MAIN_ISLAND) 回 0 → _cold_chain_fee() 回 0。
對應測試
test_weight_tiers（1001～5000 公克都是 100）、test_free_shipping_threshold_depends_on_membership（一般會員 999 元不免運）

本島、一般會員、訂單 1000 元、800 公克、常溫 → 0 元

舊版
calc(800, "main", "normal", 1000, False)：本島 → 一般會員 → 1000 ≥ 1000，f = 0。重量完全沒被看。
重構版
_ships_free() 回 True，_delivery_fee() 提早 return 0，不呼叫 _weight_fee()。這就是 guard clause：條件成立就離開，不用再包一層 else。
對應測試
test_free_shipping_threshold_depends_on_membership（一般會員剛好 1000 元免運）

本島、金卡會員、訂單 600 元、2500 公克、冷藏 → 50 元

舊版
calc(2500, "main", "gold", 600, True)：本島 → 金卡 → 600 ≥ 500，f = 0 → 跳出巢狀後 if c: 加 50。冷藏照收這條規則，要讀完整段才看得出來。
重構版
_delivery_fee() 回 0（金卡門檻 500），_cold_chain_fee() 回 50。規則寫在註解裡：# 冷藏車是另外跟物流商計費的，所以免運也要收。
對應測試
test_cold_chain_fee_is_charged_even_when_shipping_is_free、test_free_shipping_threshold_depends_on_membership（金卡 500 元免運）

離島、金卡會員、訂單 3000 元、7200 公克、冷藏 → 340 元

舊版
calc(7200, "outlying", "gold", 3000, True)：r == "main" 不成立就走 else，用第 3 份重量級距：100 + ((7200 - 5000 + 999) // 1000) * 20 + 80 ＝ 240，再加冷藏 100。這裡沒有看會員等級，是因為離島本來就不免運，但程式沒寫出這個理由。
重構版
_ships_free() 第一行就因為離島回 False → _weight_fee(7200)：超過 5000 的 2200 公克算 3 公斤，100 ＋ 60 ＝ 160 → _region_surcharge() 80 → _cold_chain_fee() 離島冷藏 100。
對應測試
test_outlying_island_never_ships_free、test_cold_chain_fee_depends_on_region、test_weight_tiers（6001 公克是 140）

重量 0 公克 → 舊版 -1，重構版丟錯誤

舊版
calc(0, "main", "normal", 800, False) 第一個判斷就不成立，回 -1。呼叫端如果沒檢查，就會把「−1 元」當成運費。
重構版
_reject_invalid() 丟 InvalidParcelError("重量必須大於 0 公克，收到 0")，後面的函式都不會執行。
行為有變
這是這次重構唯一刻意改變的地方：錯誤從回傳值變成例外。characterization.py 把舊版的 -1 和重構版的 InvalidParcelError 都換成 INVALID 再比較，所以 200 組無效輸入一樣算「結果相同」。
對應測試
test_rejects_non_positive_weight、test_legacy_error_code_maps_to_refactored_error

3. 一筆運費的旅程

以「離島、金卡會員、訂單 3000 元、7200 公克、冷藏」為例，也就是 demo.py 的第 4 筆。從示範程式建立 Parcel 到印出 340，經過這些程式碼：

  1. 建立參數物件
    demo.py 的 SAMPLES

    五個欄位都有名字，地區和會員是 Enum，不會傳錯順序，也拼不錯字。Parcel 是 @dataclass(frozen=True)，建好就不能改。

    Parcel(7200, Region.OUTLYING_ISLAND, Membership.GOLD, 3000, True)
  2. 進入點只說「做了哪兩件事」
    shipping.py 的 shipping_fee()、_reject_invalid()

    先擋掉無效輸入，再把「配送費」和「冷藏費」相加。整個函式讀起來就是一句話。重量 7200、金額 3000 都合法，_reject_invalid() 不做事。

    def shipping_fee(parcel: Parcel) -> int:
    _reject_invalid(parcel)
    return _delivery_fee(parcel) + _cold_chain_fee(parcel)
  3. 判斷免不免運
    shipping.py 的 _delivery_fee()、_ships_free()

    離島第一行就回 False，註解寫的是「為什麼」離島不免運，而不是「這裡在判斷離島」。

    def _ships_free(parcel: Parcel) -> bool:
    # 離島的物流成本高，行銷部決定不開放免運
    if parcel.region is Region.OUTLYING_ISLAND:
        return False
    return parcel.order_amount >= FREE_SHIPPING_THRESHOLD[parcel.membership]
  4. 算重量費和地區加價
    shipping.py 的 _weight_fee()、_ceil_div()、_region_surcharge()

    7200 超過 5000，多出的 2200 公克用 _ceil_div(2200, 1000) 算成 3 公斤，100 + 3 × 20 = 160。離島再加 OUTLYING_ISLAND_SURCHARGE 80，配送費 240。舊版裡同一段級距邏輯抄了 3 次，這裡只有一份。

    def _weight_fee(weight_grams: int) -> int:
    if weight_grams <= LIGHT_PARCEL_MAX_GRAMS:
        return LIGHT_PARCEL_FEE
    if weight_grams <= STANDARD_PARCEL_MAX_GRAMS:
        return STANDARD_PARCEL_FEE
    extra_kilograms = _ceil_div(
        weight_grams - STANDARD_PARCEL_MAX_GRAMS, GRAMS_PER_KILOGRAM
    )
    return STANDARD_PARCEL_FEE + extra_kilograms * FEE_PER_EXTRA_KILOGRAM
  5. 加冷藏費
    shipping.py 的 _cold_chain_fee()

    離島冷藏查 COLD_CHAIN_FEE 是 100，總計 340。

    def _cold_chain_fee(parcel: Parcel) -> int:
    # 冷藏車是另外跟物流商計費的，所以免運也要收
    return COLD_CHAIN_FEE[parcel.region] if parcel.needs_cold_chain else 0
  6. 舊版也算一次，並排印出
    demo.py 的 show_samples()

    把 Parcel 拆回 5 個位置參數、enum 換回字串（.value）餵給 calc()，印出 離島、金卡會員、訂單 3000 元、7200 公克、冷藏 → 舊版 340｜重構版 340。

  7. 裁判窮舉 728 組
    characterization.py 的 compare()

    同樣的對照做 728 次。legacy_outcome() 把 -1 換成 INVALID，refactored_outcome() 把 InvalidParcelError 換成 INVALID，其餘直接比金額。

    看 compare() 的程式碼 
    def compare(candidate: Callable[[Case], Outcome] = refactored_outcome) -> Comparison:
    """拿 candidate 的結果去比對舊版。預設比對重構版；測試會傳入故意改壞的版本。"""
    cases = tuple(input_grid())
    outcomes = tuple((legacy_outcome(case), candidate(case)) for case in cases)
    return Comparison(
        total=len(cases),
        invalid=sum(1 for old, new in outcomes if old == new == INVALID),
        mismatches=tuple(
            case for case, (old, new) in zip(cases, outcomes, strict=True) if old != new
        ),
    )

每種輸入問題在哪裡被擋下

狀況舊版重構版
重量 ≤ 0第一個 if 不成立，回 -1_reject_invalid() 丟 InvalidParcelError("重量必須大於 0 公克，收到 0")
訂單金額 < 0同上，回 -1_reject_invalid() 丟 InvalidParcelError("訂單金額不能是負數，收到 -1")
地區拼錯（"mian"）不是 "main" 就走 else，默默當成離島收 180 元建立 Region("mian") 時就丟 ValueError，根本做不出這種 Parcel
會員等級拼錯（"glod"）不是 "gold" 就當一般會員Membership("glod") 丟 ValueError
參數順序傳錯（金額和重量對調）照算，結果錯但不會報錯Parcel 的欄位有名字，用關鍵字參數建立就不會對調

後三列都不在 728 組網格裡（網格只放合法的字串），所以 characterization test 證明不到。這是窮舉比對的極限：它只能證明「測過的輸入」行為相同。拼錯字這類輸入，舊版和重構版本來就不一樣，而且是重構版比較對。

4. 啟動時發生什麼

demo.py

if __name__ == "__main__": 先呼叫 show_samples()：對 SAMPLES 的 5 筆訂單各呼叫一次 calc() 和 shipping_fee()。再呼叫 show_characterization()：跑一次 compare()，印出相同、無效、不同的組數。沒有設定檔，也不讀環境變數。

輸入網格

input_grid() 用 itertools.product 把 WEIGHTS（13 個）、REGIONS（2）、MEMBERSHIPS（2）、ORDER_AMOUNTS（7）、COLD_CHAIN（2）乘開。每個門檻都取「剛好、少 1、多 1」，例如 999、1000、1001。

測試

pytest 從 2 個測試檔收集 13 個測試函式，parametrize 展開後共 24 個。test_characterization.py 的每個測試都會重新跑一次 compare()，728 組比對很快，整套測試不到 0.1 秒。

REGIONS = ("main", "outlying")
MEMBERSHIPS = ("normal", "gold")
ORDER_AMOUNTS = (-1, 0, 499, 500, 999, 1000, 5000)
COLD_CHAIN = (False, True)

5. 關鍵設計

先有裁判，才能放心重構

重構的定義是「不改變外部行為」。舊版沒有規格文件，只有程式本身，所以拿舊版當標準答案：同一批輸入，兩版結果要一模一樣。這種測試叫 characterization test 或 golden master，適合用在「看不懂但不能改壞」的舊程式。

裁判自己也要被測

如果 compare() 寫錯，永遠回「0 組不同」，那 728 組全部相同就沒有意義。所以 compare() 可以傳入要比對的版本，test_comparison_catches_a_one_dollar_change 傳入一個「離島冷藏多收 1 元」的版本，斷言剛好抓到 11 × 2 × 6 ＝ 132 組不一致（離島冷藏的有效輸入數）。

def off_by_one_on_outlying_cold_chain(case: Case) -> Outcome:
    outcome = refactored_outcome(case)
    _, region, _, _, cold = case
    if outcome != INVALID and region == "outlying" and cold:
        return outcome + 1
    return outcome

可讀性用數字說話

./run.sh metrics 用 lizard 量每個函式，再用 ruff 的 PLR2004 規則數比較式裡的魔術數字：

指標舊版 calc()重構版（最大的那個函式）
函式數18
最長函式（NLOC，不含空行和註解）379（_weight_fee）
循環複雜度（CCN，獨立路徑數）153（_reject_invalid、_weight_fee）
認知複雜度（CogC，巢狀越深扣越多）452
參數數量52（_ceil_div；對外的 shipping_fee 只有 1 個）
比較式裡的魔術數字（ruff PLR2004）80
整個檔案的 NLOC3757

代價寫在最後一列：重構版的總行數多了一半以上，多出來的是具名常數、兩個 Enum、Parcel 和錯誤型別。Clean Code 換來的是「每一段都讀得懂」，不是「程式變短」。另外，lizard 的巢狀深度擴充（-ENS）對 Python 會把前面函式的深度累加到後面，數字不可信，所以改用把巢狀算進去的認知複雜度。

其他

設計做法在哪裡
舊版保持原樣legacy.py 不加型別、不格式化成好看的樣子，檔頭註解說明為什麼留著它legacy.py
只有一個 public 函式其他函式都加底線前綴，外面只需要知道 shipping_fee()shipping.py
對照表取代 if/else門檻和冷藏費會依會員、地區而不同，用 dict 查表，新增會員等級時改一個地方FREE_SHIPPING_THRESHOLD、COLD_CHAIN_FEE
規則寫在檔頭shipping.py 的 docstring 用白話列出 4 條規則，比讀程式快shipping.py 第 1～8 行
整數金額新台幣元用整數，_ceil_div() 用 -(-a // b) 做無條件進位，不經過浮點數_ceil_div()
三種語言結果一致.NET、Rust 版本照同一套規則實作，demo 輸出用 diff 比對逐字相同PoC 的 README「怎麼跑」
