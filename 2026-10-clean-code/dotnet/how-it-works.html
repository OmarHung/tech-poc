Clean Code 重構範例｜.NET 版運作說明

這頁說明 dotnet/ 裡的程式怎麼運作：一段故意寫得很髒的運費計算 Legacy.Calc()，照 Clean Code 原則重構成 Shipping.ShippingFee()，再用 characterization test 窮舉 728 組輸入，證明重構沒有改變行為。範例用 .NET 10（SDK 10.0.201）、C# 14，只用基礎類別庫（System.Collections.Frozen、System.Collections.Immutable、LINQ），測試用 xUnit 2.9 ＋ coverlet 6.0，可讀性用 lizard 1.24 量化。

1. 全貌 2. 互動流程圖 3. 一筆運費的旅程 4. 啟動時發生什麼 5. 關鍵設計 6. 怎麼跑

1. 全貌：舊版、重構版，和一個裁判

這份實作不開任何 port，也沒有外部服務。舊版和重構版算的是同一套運費規則；Characterization.cs 是裁判，不看規格，只看兩版在同一批輸入下的結果一不一樣。

Legacy.cs

重構前的原貌 ・ 當作行為的標準答案

一個 static class 裡的 Calc(int w, string r, string m, int a, bool c)，lizard 算 82 行（NLOC）、5 層巢狀。故意保留壞味道，不要照這樣寫。

Shipping.cs

重構版 ・ 唯一 public 的是 ShippingFee(parcel)

8 個方法，最長 13 行。Parcel（record）、Region、Membership（enum）、InvalidParcelException 各在自己的檔案。類別的 <summary> 用白話寫出全部規則。

Characterization.cs ＋ Program.cs

裁判和示範 ・ ./run.sh demo

Compare() 窮舉 13 × 2 × 2 × 7 × 2 ＝ 728 組輸入比對兩版，LegacyCodes 負責把舊版的字串換成 enum。Program.cs 先拿 5 筆訂單各算一次，再印出比對結果。

ShippingTests.cs ＋ CharacterizationTests.cs

24 個測試 ・ ./run.sh test

一邊測重構版的每條規則，一邊測「兩版結果相同」，以及「故意改壞 1 元會被抓到」。

按鈕是 Program.cs 裡的 5 筆訂單。左邊是舊版 Calc() 的巢狀決策樹，右邊是重構版的方法呼叫。藍色虛線是這筆訂單實際走的路，方框裡的 → 後面是那個方法算出來的值，紅色是錯誤。

舊版
Legacy.Calc(2500, "main", "normal", 800, false)：過了驗證 → 本島 → 一般會員 → 800 < 1000 不免運 → 在第 5 層巢狀查第 2 份重量級距：2500 ≤ 5000，100 元 → 常溫不加錢。
重構版
ShipsFree() 回 false（未達一般會員門檻 1000）→ WeightFee(2500) 回 100、RegionSurcharge(Region.MainIsland) 回 0 → ColdChainFee() 回 0。
對應測試
ChargesByWeightTier（1001～5000 公克都是 100）、FreeShippingThreshold_DependsOnMembership（一般會員 999 元不免運）

本島、一般會員、訂單 1000 元、800 公克、常溫 → 0 元

舊版
Legacy.Calc(800, "main", "normal", 1000, false)：本島 → 一般會員 → 1000 ≥ 1000，f = 0。重量完全沒被看。
重構版
ShipsFree() 回 true，DeliveryFee() 提早 return 0，不呼叫 WeightFee()。這就是 guard clause：條件成立就離開，不用再包一層 else。
對應測試
FreeShippingThreshold_DependsOnMembership（一般會員剛好 1000 元免運）

本島、金卡會員、訂單 600 元、2500 公克、冷藏 → 50 元

舊版
Legacy.Calc(2500, "main", "gold", 600, true)：本島 → 金卡 → 600 ≥ 500，f = 0 → 跳出巢狀後 if (c) 加 50。冷藏照收這條規則，要讀完整段才看得出來。
重構版
DeliveryFee() 回 0（金卡門檻 500），ColdChainFee() 回 50。規則寫在註解裡：// 冷藏車是另外跟物流商計費的，所以免運也要收。
對應測試
ColdChainFee_IsChargedEvenWhenShippingIsFree、FreeShippingThreshold_DependsOnMembership（金卡 500 元免運）

離島、金卡會員、訂單 3000 元、7200 公克、冷藏 → 340 元

舊版
Legacy.Calc(7200, "outlying", "gold", 3000, true)：r == "main" 不成立就走 else，用第 3 份重量級距：100 + ((7200 - 5000 + 999) / 1000) * 20 + 80 ＝ 240，再加冷藏 100。這裡沒有看會員等級，是因為離島本來就不免運，但程式沒寫出這個理由。
重構版
ShipsFree() 第一行就因為離島回 false → WeightFee(7200)：超過 5000 的 2200 公克算 3 公斤，100 ＋ 60 ＝ 160 → RegionSurcharge() 80 → ColdChainFee() 離島冷藏 100。
對應測試
OutlyingIsland_NeverShipsFree、ColdChainFee_DependsOnRegion、ChargesByWeightTier（6001 公克是 140）

重量 0 公克 → 舊版 -1，重構版丟例外

舊版
Legacy.Calc(0, "main", "normal", 800, false) 第一個判斷就不成立，回 -1。呼叫端如果沒檢查，就會把「−1 元」當成運費。
重構版
RejectInvalid() 丟 InvalidParcelException，Message 是「重量必須大於 0 公克，收到 0」，後面的方法都不會執行。
行為有變
這是這次重構唯一刻意改變的地方：錯誤從回傳值變成例外。Characterization.cs 把舊版的 -1 和重構版的 InvalidParcelException 都換成 Outcome.Invalid 再比較，所以 200 組無效輸入一樣算「結果相同」。
對應測試
Rejects_NonPositiveWeight、LegacyErrorCode_MapsToRefactoredError

3. 一筆運費的旅程

以「離島、金卡會員、訂單 3000 元、7200 公克、冷藏」為例，也就是 Program.cs 的第 4 筆。從示範程式建立 Parcel 到印出 340，經過這些程式碼：

  1. 建立參數物件
    Parcel.cs、Program.cs 的 samples

    五個欄位都有名字，地區和會員是 enum，拼不錯字；兩個 enum 是不同型別，位置放反會編譯失敗。Parcel 是 sealed record，屬性只能在建立時設定，建好就不能改，要改只能用 with 做一份新的。

    public sealed record Parcel(
    int WeightGrams,
    Region Region,
    Membership Membership,
    int OrderAmount,
    bool NeedsColdChain);

// Program.cs 的 samples 第 4 筆
new(7200, Region.OutlyingIsland, Membership.Gold, 3000, true),
  2. 進入點只說「做了哪兩件事」
    Shipping.cs 的 ShippingFee()、RejectInvalid()

    先擋掉無效輸入，再把「配送費」和「冷藏費」相加。整個方法讀起來就是一句話。重量 7200、金額 3000 都合法，RejectInvalid() 不做事。

    public static int ShippingFee(Parcel parcel)
{
    RejectInvalid(parcel);
    return DeliveryFee(parcel) + ColdChainFee(parcel);
}
  3. 判斷免不免運
    Shipping.cs 的 DeliveryFee()、ShipsFree()

    離島第一行就回 false，註解寫的是「為什麼」離島不免運，而不是「這裡在判斷離島」。

    private static bool ShipsFree(Parcel parcel)
{
    // 離島的物流成本高，行銷部決定不開放免運
    if (parcel.Region == Region.OutlyingIsland)
    {
        return false;
    }
    return parcel.OrderAmount >= FreeShippingThreshold[parcel.Membership];
}
  4. 算重量費和地區加價
    Shipping.cs 的 WeightFee()、CeilDiv()、RegionSurcharge()

    7200 超過 5000，多出的 2200 公克用 CeilDiv(2200, 1000) 算成 3 公斤，100 + 3 × 20 = 160。離島再加 OutlyingIslandSurcharge 80，配送費 240。舊版裡同一段級距邏輯抄了 3 次，這裡只有一份。

    private static int WeightFee(int weightGrams)
{
    if (weightGrams <= LightParcelMaxGrams)
    {
        return LightParcelFee;
    }
    if (weightGrams <= StandardParcelMaxGrams)
    {
        return StandardParcelFee;
    }
    var extraKilograms = CeilDiv(weightGrams - StandardParcelMaxGrams, GramsPerKilogram);
    return StandardParcelFee + extraKilograms * FeePerExtraKilogram;
}
  5. 加冷藏費
    Shipping.cs 的 ColdChainFee()

    離島冷藏查 ColdChainFeeByRegion 是 100，總計 340。

    private static int ColdChainFee(Parcel parcel)
{
    // 冷藏車是另外跟物流商計費的，所以免運也要收
    return parcel.NeedsColdChain ? ColdChainFeeByRegion[parcel.Region] : 0;
}
  6. 舊版也算一次，並排印出
    Program.cs 的 ShowSamples()

    把 Parcel 拆回 5 個位置參數，enum 用 LegacyCodes.ToCode() 換回字串，餵給 Legacy.Calc()，印出 離島、金卡會員、訂單 3000 元、7200 公克、冷藏 → 舊版 340｜重構版 340。

  7. 裁判窮舉 728 組
    Characterization.cs 的 Compare()

    同樣的對照做 728 次。LegacyOutcome() 把 -1 換成 Outcome.Invalid，RefactoredOutcome() 先用 LegacyCodes 把字串換成 enum 建出 Parcel，再把 InvalidParcelException 換成 Outcome.Invalid，其餘直接比金額。

    看 Compare() 的程式碼 
    public static Comparison Compare() => Compare(RefactoredOutcome);

/// <summary>拿 candidate 的結果去比對舊版。不帶參數時比對重構版；測試會傳入故意改壞的版本。</summary>
public static Comparison Compare(Func<Case, Outcome> candidate)
{
    var results = InputGrid()
        .Select(input => (Case: input, Old: LegacyOutcome(input), New: candidate(input)))
        .ToImmutableArray();
    return new Comparison(
        Total: results.Length,
        Invalid: results.Count(result => result.Old.IsInvalid && result.New.IsInvalid),
        Mismatches: [.. results.Where(result => result.Old != result.New).Select(result => result.Case)]);
}

狀況舊版重構版
重量 ≤ 0第一個 if 不成立，回 -1RejectInvalid() 丟 InvalidParcelException：「重量必須大於 0 公克，收到 0」
訂單金額 < 0同上，回 -1RejectInvalid() 丟 InvalidParcelException：「訂單金額不能是負數，收到 -1」
地區拼錯（"mian"）不是 "main" 就走 else，默默當成離島收 180 元C# 的 enum 不能是字串，舊字串要經過 LegacyCodes.ToRegion("mian") 才變成 Region，查不到就丟 KeyNotFoundException，根本做不出這種 Parcel。直接寫 C# 時打成 Region.Mian 是編譯錯誤
會員等級拼錯（"glod"）不是 "gold" 就當一般會員LegacyCodes.ToMembership("glod") 丟 KeyNotFoundException
參數順序傳錯（金額和重量對調）照算，結果錯但不會報錯Parcel 是 record，可以用具名參數建立（new Parcel(WeightGrams: 2500, …)，ShippingTests 的 Baseline 就這樣寫），對調了一眼看得出來。重量和金額都是 int，只用位置參數還是可能放反；地區和會員是不同的 enum，放反會編譯失敗

後三列都不在 728 組網格裡（網格只放合法的字串），所以 characterization test 證明不到。這是窮舉比對的極限：它只能證明「測過的輸入」行為相同。拼錯字這類輸入，舊版和重構版本來就不一樣，而且是重構版比較對。

4. 啟動時發生什麼

Program.cs

用 top-level statements 寫，依序建好 regionLabels、membershipLabels（兩張 FrozenDictionary）和 samples 陣列，接著呼叫 ShowSamples()：對 5 筆訂單各呼叫一次 Legacy.Calc() 和 Shipping.ShippingFee()。再呼叫 ShowCharacterization()：跑一次 Compare()，印出相同、無效、不同的組數（相同 ＝ 總數 − 無效 − 不同）。沒有設定檔，也不讀環境變數。./run.sh demo 用 dotnet run -c Release，第一次會先建置。

輸入網格

InputGrid() 用 LINQ 查詢語法連寫 5 個 from，把 Weights（13 個）、Regions（2）、Memberships（2）、OrderAmounts（7）、ColdChain（2）乘開，最後一個 from 變化最快，順序和 Python 版的 itertools.product 一樣。每個門檻都取「剛好、少 1、多 1」，例如 999、1000、1001。

測試

xUnit 從 2 個測試類別找到 13 個測試方法，[Theory] 的 [InlineData] 展開後共 24 個。CharacterizationTests 的每個測試都會重新跑一次 Compare()，整套測試約 30 毫秒。coverlet 量到 Shipping、Characterization、Legacy 都是 100%；整個專案 77.5%，沒涵蓋的是測試不會跑的 Program.cs 和只有 demo 用的 LegacyCodes.ToCode()。

5. 關鍵設計

先有裁判，才能放心重構

重構的定義是「不改變外部行為」。舊版沒有規格文件，只有程式本身，所以拿舊版當標準答案：同一批輸入，兩版結果要一模一樣。這種測試叫 characterization test 或 golden master，適合用在「看不懂但不能改壞」的舊程式。

裁判自己也要被測

如果 Compare() 寫錯，永遠回「0 組不同」，那 728 組全部相同就沒有意義。所以 Compare() 有一個多載可以傳入要比對的版本，Comparison_CatchesAOneDollarChange 傳入一個「離島冷藏多收 1 元」的版本，斷言剛好抓到 11 × 2 × 6 ＝ 132 組不一致（離島冷藏的有效輸入數）。

static Outcome OffByOneOnOutlyingColdChain(Case input)
{
    var outcome = Characterization.RefactoredOutcome(input);
    if (!outcome.IsInvalid && input.Region == "outlying" && input.Cold)
    {
        return new Outcome(outcome.Fee + 1);
    }
    return outcome;
}

可讀性用數字說話

./run.sh metrics 用 lizard 量 Legacy.cs 和 Shipping.cs 的每個方法。Python 版另外用 ruff 的 PLR2004 數比較式裡的魔術數字，那是 Python 專用的規則，.NET 版不量這一項。

指標舊版 Calc()重構版（最大的那個方法）
方法數18
最長方法（NLOC，不含空行和註解，只有大括號的行也算）8213（WeightFee）
循環複雜度（CCN，獨立路徑數）153（RejectInvalid、WeightFee）
認知複雜度（CogC，巢狀越深扣越多）452（RejectInvalid、WeightFee）
參數數量52（CeilDiv；對外的 ShippingFee 只有 1 個）
整個檔案的 NLOC8676（Shipping.cs；Parcel、兩個 enum、例外在另外 4 個檔案，共 21 行）

舊版 82 行，是 Python 版 37 行的兩倍多，差在格式不在邏輯：C# 的大括號照 dotnet format 的預設各佔一行，lizard 也把這些行算進 NLOC；變數還得先宣告 int f;（C# 規定變數讀取前一定要有值）。CCN、CogC、參數數量和 Python 版一模一樣。重構版的方法拆法也和 Python 相同，每個方法的 CCN 都對得上；唯一的差別是 RegionSurcharge 的 CogC：這裡量到 0，Python 版是 1。lizard 1.24.3 對 C# 三元運算子（?:）的 CogC 時算時不算（CCN 都有算），是工具的問題，不是程式不同。代價在最後一列：重構版加上型別檔共 97 行，比舊版多一些；Python 版多了一半以上，這裡差得少，是因為舊版的大括號已經佔掉很多行。

其他

設計做法在哪裡
舊版保持原樣照 Python 版逐行搬：縮寫、5 個位置參數、巢狀、魔術數字、f = f + 50 都不改，檔頭註解說明為什麼留著它。編譯器和分析器對它沒有發警告，所以不需要局部抑制Legacy.cs
只有一個 public 方法其他方法和所有常數都是 private，外面只需要知道 ShippingFee()Shipping.cs
對照表取代 if/else門檻和冷藏費會依會員、地區而不同，用 FrozenDictionary 查表（建好就不能改，查詢有最佳化），新增會員等級時改一個地方。冷藏費的表叫 ColdChainFeeByRegion，因為 C# 的欄位不能和 ColdChainFee() 方法同名FreeShippingThreshold、ColdChainFeeByRegion
舊字串和 enum 的對照集中一處Python 版直接把 "main" 當 enum 的值；C# 的 enum 底層是整數，所以雙向對照放在 LegacyCodes：比對時用 ToRegion()、ToMembership()，demo 呼叫舊版時用 ToCode()LegacyCodes.cs
錯誤型別InvalidParcelException 繼承 ArgumentException（對應 Python 的 ValueError），只傳訊息、不傳 paramName，Message 後面才不會多出 (Parameter '...')InvalidParcelException.cs
整數金額新台幣元用 int，CeilDiv() 用 (a + b - 1) / b 無條件進位，不經過浮點數。C# 的整數除法往 0 截斷，照抄 Python 的 -(-a // b) 會變成無條件捨去；這裡只會收到正數，所以這個寫法成立CeilDiv()
比對結果的型別Python 的 int | "invalid" 改成 readonly record struct Outcome(int? Fee)，Fee 是 null 就是無效（Outcome.Invalid）。Case 也是 record struct，比較的是值，Assert.Distinct 能直接檢查網格沒有重複Outcome.cs、Case.cs
用多載取代預設參數C# 的預設參數只能是常數，不能是方法，所以 Compare() 轉呼叫 Compare(RefactoredOutcome)Characterization.cs
測試的預設訂單不寫帶預設參數的工廠函式，改用一個 Baseline record，每個測試用 with 只改相關欄位。錯誤訊息比對整句（Python 版只比開頭）ShippingTests.cs
輸出不受語系影響開 InvariantGlobalization：有些語系的負號是 U+2212，會讓 -1 印得和 Python 版不一樣Directory.Build.props
規則寫在檔頭Shipping 類別的 <summary> 用白話列出 4 條規則，比讀程式快Shipping.cs 第 5～13 行
三種語言結果一致Python、Rust 版本照同一套規則實作，demo 輸出用 diff 比對逐字相同PoC 的 README「怎麼跑」
